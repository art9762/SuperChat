# SuperChat Messenger

Консольный P2P мессенджер с шифрованием сообщений на базе Python, urwid и SQLite.
Мессенджер работает по гибридной архитектуре: клиенты общаются напрямую друг с другом по IP (в локальной сети или через прямой интернет), а если P2P-соединение невозможно — обмениваются сообщениями через центральный релей-сервер.

## 🚀 Установка для пользователей

### 1. Как запустить Сервер (на выделенном хосте/ПК)
Вам не нужно клонировать репозиторий, если у вас установлен **Docker**. Сервер опубликован в реестре GitHub. Достаточно выполнить одну команду:

```bash
docker run -d -p 8888:8888 --name superchat-server ghcr.io/art9762/superchat:latest
```
*(Убедитесь, что порт 8888 открыт в вашем файрволе для входящих TCP-соединений).*

**Обновление сервера:**
Если вышло обновление и вы хотите переустановить сервер, выполните эти 3 команды:
```bash
docker pull ghcr.io/art9762/superchat:latest
docker rm -f superchat-server
docker run -d -p 8888:8888 --name superchat-server ghcr.io/art9762/superchat:latest
```

---

### 2. Установка Клиента (Мессенджера)
Клиенту не нужен Docker. Для установки скопируйте и выполните **одну команду** в вашем терминале (убедитесь, что у вас установлен `Python 3` и `Git`):

**Для MacOS и Linux (bash/zsh):**
```bash
curl -sSL https://raw.githubusercontent.com/art9762/SuperChat/main/install.sh | bash
```

**Для Windows (PowerShell):**
Откройте PowerShell и вставьте команду:
```powershell
iwr -useb https://raw.githubusercontent.com/art9762/SuperChat/main/install.ps1 | iex
```

Скрипт автоматически:
- Скачает мессенджер в `~/.superchat`.
- Настроит изолированное Python окружение.
- Установит все зависимости.
- Создаст исполняемую команду.

После установки вы сможете запускать мессенджер из любого места простой командой:
```bash
superchat
```

### 📎 Отправка файлов (E2EE)
Мессенджер поддерживает защищенную гибридным E2E-шифрованием (RSA + AES) отправку файлов и изображений!
Чтобы отправить собеседнику файл, напишите в поле ввода команду `/send` и путь к вашему файлу:
```
/send /Users/myname/Desktop/photo.jpg
```
Полученные файлы автоматически сохраняются в папку `~/.superchat/downloads/`.

Размер одного файла — до **10 МиБ включительно**, как для P2P, так и для relay. Обновите оба клиента и сервер: старые версии используют сетевой предел около 64 КиБ и не поддерживают такие вложения. Новый предел одной строки протокола — 32 МиБ с учётом шифрования и Base64.

Входящее имя принимается только как имя файла, без каталогов. Уже существующие файлы и символические ссылки не перезаписываются: повторное вложение сохраняется как `name (1).ext`, затем `name (2).ext`. Некорректные имена, Base64 и вложения сверх лимита отклоняются.

При локальной ошибке отправки интерфейс сообщает о ней, а сообщение не добавляется в историю как отправленное. Успешная отправка означает передачу данных в P2P-соединение или релей; протокол пока не подтверждает получение/расшифровку адресатом и не хранит очередь для офлайн-пользователей.

P2P-подключение ограничено 5 секундами, запись в транспорт — 30 секундами. Если P2P-собеседник перестаёт читать, клиент закрывает соединение и пробует relay. Зависшее закрытие принудительно прерывается через секунду. При таймауте relay отправка завершается ошибкой и соединение пересоздаётся.

*Адрес подключения задаётся константами `SERVER_HOST` и `SERVER_PORT` в `client/ui.py`; для собственного сервера измените их перед запуском. Тесты используют только `127.0.0.1`, временную БД, временные ключи и созданные для проверки файлы.*

Шифрование не заменяет проверку личности: в текущем протоколе нет проверки ключей собеседника, подписи отправителя и защиты от подмены регистрации на релей-сервере. Схема не является протоколом Signal.

## 🏗️ Разработка и локальная сборка
Если вы хотите собрать Docker образ сервера самостоятельно (из исходников), мы предусмотрели скрипты в `Makefile`. Так как образ мульти-архитектурный, вы можете собрать его под свой ПК или сервер:

- Для сборки образа под сервер Linux/Ubuntu (x86_64 / amd64):
  ```bash
  make build-amd64
  ```
- Для сборки образа под Apple Silicon Mac / Raspberry Pi (arm64):
  ```bash
  make build-arm64
  ```

## Проверки

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r client/requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

На Windows используйте `.venv\Scripts\python.exe`. Проверки включают настоящий обмен зашифрованными файлами 256 КиБ по P2P и через локальный релей. Публичный сервер и личные файлы не используются.
